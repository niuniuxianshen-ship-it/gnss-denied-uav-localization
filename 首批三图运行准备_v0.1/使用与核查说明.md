## 接口与拟定设置

官方地址`https://api.deepseek.com`，上传`POST /files`，定位`POST /chat/completions`。定位固定deepseek-flash、`thinking={"type":"disabled"}`、temperature=0、max_tokens=8192、stream=false、`response_format={"type":"text"}`、`tool_choice="none"`；不提供tools，不添加system消息，不发送seed、detail或分辨率参数，也不额外发送top_p、stop、n、reasoning_effort等字段。temperature=0不保证服务端完全确定。

Files表单仅含匿名文件名（IMG001.png等）、原PNG字节、purpose=user_data、`expires_after[anchor]=created_at`、`expires_after[seconds]=604800`。本批最大图片15,590,941字节、最长边4889像素，符合本次查阅的上传大小及单图尺寸上限；这只是本地前置检查。服务端实际图像处理与实际接口兼容性**未确认**，不能声称原生像素均会进入推理。

上传超时暂定120秒，定位超时暂定300秒，均待审阅、未实测；实际归档分别登记。标准库http.client的timeout作用于连接和各次socket操作，**不是整个请求总墙钟上限**。无SDK、无客户端自动重试，不跟随重定向，不自动读取代理环境变量或凭据文件；使用默认TLS证书校验。只有对应显式执行分支会读取DEEPSEEK_API_KEY，且不打印或存储密钥、认证头。本轮未进入该分支。

编码前已查阅[DeepSeek官方GitHub Files实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-deepseek/src/files-api.ts)与[MIT许可](https://github.com/deepseek-ai/deepseek-harness/blob/master/LICENSE)，参考表单与拒绝重定向的思路，未复制或引入仓库代码。该实现使用Anthropic适配，其响应字段及大小限制不直接照搬。Chat接口字段采用官方[Upload File](https://api-docs.deepseek.com/api/create-file/)、[Vision](https://api-docs.deepseek.com/guides/vision)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)文档：图片用`{"type":"file","file_id":真实ID}`引用；上传返回按object、bytes、filename、purpose、created_at、expires_at核对。若缺少预期7天有效期或字段不符则停止，不追加探测。官方文档查询未发送照片或研究材料，也不是API远程探测。

## 使用、首次归档与停止规则

本机Python 3.10.0及标准库，未安装依赖；其他Python版本未验证。在PowerShell中：

```powershell

python -X utf8 -B "$prep\run_batch.py" check
python -X utf8 -B "$prep\check_offline.py"
```

无参数或prepare执行离线生成。本轮已生成，重复运行会以退出码2拒绝覆盖；不要删除交付物来重建。check只读验证6项输入、配置／程序及模板字节；`check --submission-ready`还检查真实上传档案、ID和过期时间，当前应拒绝。源输入、配置或程序变化后应另建版本并审阅，不自动更新哈希。

**下列是未来审阅并另行授权后的入口用法，本轮未执行：**

```powershell
python -X utf8 -B "$prep\run_batch.py" upload --execute-upload
python -X utf8 -B "$prep\run_batch.py" run --execute-run
```

仅写upload或run而无对应开关会拒绝，不读取凭据。上传阶段最多3个首次请求，定位阶段最多6个；两个命令不能合并。定位前须取得三份完整且与图片相符的真实上传记录，ID有效且互不相同；每次定位前再核对输入和有效期。没有ID、输入变化或已有本阶段档案时拒绝执行，不以占位ID代替，不自动重新上传过期文件。

未来档案固定在本目录的`运行档案/上传`和`运行档案/定位`，每项单独子目录。每阶段先独占建立目录并保存stage_start.json顺序登记，每项先建立独占目录和attempt.json占用标记，再保存首次request.json并最多发送一次。上传另存精确request.multipart.bin；定位request.json就是实际JSON正文，不含认证信息。保留response.json原始响应字节（即使错误正文不是合法JSON）、可取得的output.txt、metadata.json；记录实际返回模型、finish_reason、用量、起止及耗时、输入／请求／响应哈希、超时、技术失败和缺失文件。读响应中断时保留已取得字节；无响应或无正文时如实登记缺失，不补造文件。硬中断可能留下不完整档案，占用目录仍阻止重复执行。

阶段结束另存summary.json，列已尝试、完成、未执行项及停止原因。HTTP、连接／超时、解析、空正文、非正常结束／截断、工具调用或必要档案失败时停止后续项；整个已尝试阶段都不续跑、不重试、不切换模型、不覆盖首次记录。网络尝试标记不证明服务器已收到请求，失败时不自动补做。答错、文本拒答或输出格式偏差不作为重试触发条件；此入口不评价地理答案或计算指标。completed只表示本程序的技术检查状态。
