# CASE 设计目的（管理专用）

不发给评分者；不作为独立评分 API 输入。

## CASE_012

目的：测试有区分力的文字线索如何形成有条件的相对优势。

关注：关注证据与排序的联系，而不是所选省份的真假；公告来源未实证核验。

## CASE_013

目的：测试共同支持、证据缺口和暂定顺序能否构成充分比较。

关注：拒答不是判分依据，需看无法区分的说明及排序影响。

## CASE_014

目的：测试共同线索已表达、相对排序作用未解释的情形。

关注：不能因排第一就认定无依据优势断言，也不能因提到共同线索就判充分。

## CASE_015

目的：测试只有排序、没有候选间比较的情形。

关注：泛称需要更多线索不等于说明候选无法区分。

## CASE_016

目的：测试明确优势断言与共同支持依据之间的关系。

关注：不得由评分者补充云南独有特征，谨防用最终结论代替比较评价。

## CASE_017

目的：测试整体相似感、未展开的记忆依据和明确优势断言之间的解释边界。

关注：现有规则未要求模型已有知识均独立核验；不能自动把相似性或未核验知识判为虚构，也不能替它补写区分特征。

## CASE_018

目的：测试完整输出只列一个候选的适用条件。

关注：不以单候选缺少比较为由给0分。

## CASE_019

目的：测试完整输出明确无候选的适用条件。

关注：不能与原始输出未保存混淆。

## CASE_020

目的：测试原始输出完全未保存。

关注：存档注不是模型的无候选回答；适用条件无法确认。

## CASE_021

目的：测试列出多候选但全部比较理由在未保存附表中的材料缺口。

关注：应区分未保存的比较材料与已存完整输出没有比较；不把缺照片自动当第②项未评。
