# 人工 CASE 扩展 v0.2 设计说明

本轮检验固定评分表 v0.2 第②项是否覆盖更多候选比较场景，以及两名评分者能否区分 0、1、2 分、不适用、未评。案例为人工文本，不检验定位准确率、C-v2 效果或模型能力；不运行照片定位模型。

## 版本与身份

材料版本：人工CASE扩展_v0.2。案例编号为 CASE_012—CASE_021。此前参考案例_v0.3 存在相同编号，但文本不同；本轮不替换旧文本，不合并旧评分。记录身份由材料版本、批次号、案例编号和评分项共同确定。

## 先行设计

本说明和 CASE覆盖矩阵.csv 在案例文本、参考判分依据和评分包之前创建。覆盖矩阵固定本轮十个案例的类型、目标和风险。

新案例用于测试评分表，不用于修改评分表。

固定评分材料使用现存候选比较评分表_v0.2.md 的完整字节副本。空白记录使用现存评分记录_空白.csv 的完整字节副本，不修改规则、表头或模板。评分只针对第②项；其他项目不代替第②项。

## 六类覆盖与材料边界

覆盖充分比较、比较不充分、无比较或无依据优势、不适用、未评及潜在争议边界。管理文件中的参考判断是设计者暂定判断，不是独立评分结果。边界案例保留解释分支，不用参考判断干预评分者。

缺少实际照片本身不自动使第②项未评。本轮依据所存模型文字评价比较是否有依据；输出或不可替代的比较材料缺失、致使无法判断时，才按现有评分表处理。存档注属于材料可用性说明，不能算模型表达的比较理由。

## 发放与独立评分

发放包仅含阅读说明、评分表 v0.2、空白记录及十份案例，共十三个文件。设计说明、覆盖矩阵、管理索引、参考判分依据和静态审查记录不发送给评分 API。A、B 接收同一发放包的字节副本，以同模型、同请求设置、各一次新 API 请求独立完成评分；没有对话历史，不提供对方结果或逐案例提示。无法确认的服务条件记录为未确认，不声称已隔离。

首次完整响应和原始提交保存后锁定。HTTP、解析或格式失败照实归档，不修正或覆盖。两份合格提交形成前不计算双评分一致性。

## 统计与冻结

数字一致率仅使用双方均给出有效 0—2 分的配对案例，明确分子、分母、纳入数与逐项排除原因。数字、不适用、未评分别统计；适用条件分歧、等级分歧、同分理由差异分别记录。讨论或裁定另存，不覆盖原始记录。

先审查原句与理由再作冻结判断。没有新规则问题时，可形成只增加程序字段和案例说明的评分协议 v0.3；出现不能静态解决的规则歧义时，保存问题清单，不直接改动评分标准，不把一致率解释成规则有效性的证明。
