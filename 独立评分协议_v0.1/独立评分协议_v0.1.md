# 独立评分协议 v0.1

状态：静态审查完成，待冻结。评分规则固定为评分表v0.2；案例清单、评分者及锁定信息尚未填写。没有执行独立评分，没有一致率结果。本协议规定记录与分析方法，不修改原始评分表。

## 1. 核心协议

1. 两名评分者使用相同的案例材料和固定的评分表v0.2，独立完成评分。
2. 分别保存原始评分、评分依据、适用状态和评分时间。
3. 数字评分一致率仅使用双方均给出0—2分的案例计算，报告纳入数量与排除原因。
4. 适用条件分歧和评分等级分歧分别记录。
5. 原始评分锁定后才能讨论分歧；裁定结果另外保存，不覆盖原始记录。
6. 如需修改评分规则，保存为新版本，不追溯改写原始评分。

## 2. 固定评分材料

固定依据是本目录[材料/候选比较评分表_v0.2.md](材料/候选比较评分表_v0.2.md)。该文件是现有评分表的字节一致副本，SHA256为`C33B5241A70919DB7B334AB67D75E9A460667B0A999A2E3B577BEB718B69D2D1`。原评分表和原草稿保留，不覆盖。评分规则及协议附件的文件哈希记入[材料版本清单.json](材料版本清单.json)。

每个案例对应一份实际模型输出；同一张图片的不同输出是不同案例，使用唯一案例编号。编号不含地点答案。通过[案例材料登记_空白.csv](模板/案例材料登记_空白.csv)固定：

- 案例编号、图片匿名编号及SHA256；实际提交的图片文件。
- 完整提示词的版本、文件及SHA256；不能只写“A/B/C”。明确是否包含C-v2新增条款，不据新条款追溯认定旧输出违规。
- 实际共同附录的版本、文件及SHA256。
- 首次原始输出文件及SHA256；原始响应文件如有，一并固定。明确评分文本范围，例如仅最终正文；双方必须相同，不可一人使用推理字段而另一人不使用。
- 允许评分者查看的材料范围、是否包含推理字段、材料缺失情况。默认不加入答案标签、来源清单、先前评分或审查结论；如确需加入，评分前明列并对两人一致提供。
- 评分表版本和哈希；协议版本；案例材料登记锁定时间。

案例清单由实际材料登记，不生成虚构案例或输出。现有开发图和旧试跑不自动入选。材料缺失可以作为真实案例状况记录，不能补写缺少的内容；允许何种材料范围须在评分前固定。

共同材料若有错误，双方评分前修订材料清单并重新核对哈希。开始评分后发现问题时，保留原版本及评分，登记影响范围；后续新材料或新规则使用另一个批次编号。

## 3. 独立评分记录

为两名评分者登记不同标识，身份映射及承担裁定的人或方式在开始前固定。每人使用[原始评分记录_空白.csv](模板/原始评分记录_空白.csv)的独立副本，保存于各自文件。不得用一张共享表实时协商填写，也不得查看另一人的记录或先前裁定。

一条记录对应一个“案例编号 × 评分项①/②/③/④”。每人对每个案例的四项都作记录，包括不适用或未评，不能删掉这些项来改变分母。各项独立，不加权、不求总分。

|字段|填写规定|
|--|--|
|批次、协议及评分表版本/哈希|与固定材料一致|
|案例编号、材料登记文件哈希|连接到同一材料集|
|评分者标识、评分项|匿名标识；①/②/③/④|
|适用判断|适用／不适用／无法确认；依据评分表对应条件填写|
|评分处理状态|数字评分／不适用／未评，与数字分分开存储|
|数字分|仅填0、1、2；不适用或未评时留空，不用0、-1或其他数代替|
|适用状态理由|说明条件成立、不成立或无法确认的依据；不适用和未评必须说明原因|
|所依据规则原句|引用评分表和必要的实际提示词条款，保留原句及位置|
|原始输出引文及位置|逐字引用，并记录行号、字段或段落；确实缺少相应表达时写“未说明”并注明已检查范围，不能伪造引文|
|画面核对位置及知识核验状态|第④项标出可核对位置；画面无法核实时如实记载。地理知识未核验不自动等同视觉编造|
|判分理由、待核实项|分别保存，不能以待核实事项冒充已有依据|
|开始和提交时间|ISO 8601，含时区；本地时间使用+08:00。未评分时保持空白|

数字评分需要适用判断为“适用”；不适用对应条件明确不成立；“未评”表示必要材料或核实条件不足，不自动等于不适用。此时适用判断可以为“适用”或“无法确认”，须按实际依据填写。两名评分者可能对适用性判断不同，原样保留，不预先统一。

模板中的空白是待填，不是“未评”结果，也不是0分。缺记录、重复记录、版本或材料哈希不符、处理状态与分数矛盾，属于记录完整性问题，单列处理，不擅自改成有效评分。

## 4. 原始记录锁定

两人独立完成后，分别提交原始文件。按[原始记录锁定_空白.csv](模板/原始记录锁定_空白.csv)保存各文件SHA256、评分者标识、提交时间、锁定时间及核对人。锁定以文件哈希和保存的锁定记录为准，不声称仅靠文件夹或只读属性实现权限隔离。

锁定前仅检查字段、版本、完整性和配对关系，不讨论分数或理由。如需评分者修复缺字段，修复前文件另存，修复后作为新的提交版本，记录关联；不得借完整性检查协调评分。

两份原始记录都锁定后，才开放比较和讨论。锁定后发生的任何更正另存追加记录，保留原始值、理由、时间和哈希。首次一致率使用锁定的原始记录；更正后的分析若开展，另标分析版本，不替代首次结果。

## 5. 配对、分歧分类和统计

按“批次 + 案例编号 + 评分项”配对两个指定评分者，评分者不是统计单位。四项分别报告，主要统计单位为“案例 × 评分项”，不能把某一项的分母写成全部评分记录数。

先按冻结的案例清单确定每项计划配对数N，再检查两人的记录。缺记录、重复、字段无效或材料不匹配的记录计入排除清单，不能静默删掉。完整性问题解决前不纳入有效配对。

|分类|定义|记录方式|
|--|--|--|
|适用条件分歧|一人判“适用”，另一人判“不适用”|分别引用两人的适用依据；不混入数字等级分歧|
|适用判断待确认|至少一人判“无法确认”|记录材料或判断缺口，不强行归为适用／不适用分歧|
|评分处理状态分歧|数字评分、不适用、未评三种处理状态不同|记录双方原状态；可与适用判断问题同时存在，不能加总当成互斥案例数|
|评分等级分歧|双方有效记录均为数字评分，但分数不同|记录0/1、0/2或1/2及各自依据|
|完整性问题|缺记录、重复、无效字段、材料/版本不符等|单列，不当作模型质量分歧|

每项数字评分一致率严格采用：

- D：两人有效记录均给出0、1或2分的配对数。
- E：上述D中两人数值完全相同的配对数。
- 一致率=E/D，报告为“E ÷ D”，同时报告N、有效配对数V、数字等级分歧数D−E，以及排除数N−D。
- D=0时写“无双方数字评分配对，不计算”，不报告0%或100%。未填真实记录时写“尚未统计”，不把空白模板算成零个案例的结果。

为每项保存含案例编号的排除明细；统计汇总使用如下互斥主原因。先处理完整性问题，其余按双方处理状态分类，不重复计数：

1. 完整性问题（具体原因另列）；
2. 双方不适用；
3. 双方未评；
4. 一方数字评分、另一方不适用；
5. 一方数字评分、另一方未评；
6. 一方不适用、另一方未评。

方向和双方的具体理由仍保留。六类排除主原因合计须等于N−D；V须等于N减去完整性排除数；E≤D≤V≤N。不适用和未评之间的分歧不进入数字一致率，但必须出现在状态配对及分歧记录中。

另保存三种处理状态的3×3配对计数表，以一名评分者为行、另一名为列，包含V个有效配对，不将双方不适用或双方未评计入E。适用判断及其无法确认情况单列计数，不与等级分歧相加。需要另算状态一致率时必须另报指标名称、分子、分母与排除原因，不能称作数字评分一致率。

使用[统计报告_空白.md](模板/统计报告_空白.md)。本版不设通过阈值，不计算加权总分或把置信分数当概率。若另报跨项汇总，只能明确标为辅助“案例×评分项”汇总，并同时保留四项各自的分子分母；不能称为案例整体一致率，也不能代替逐项报告。

## 6. 讨论和裁定

原始记录锁定后，对分歧使用[分歧及裁定记录_空白.csv](模板/分歧及裁定记录_空白.csv)。每条记录关联两个原始文件哈希及原始记录键，保存：分歧类型、双方原状态和分数、双方原句和理由、讨论时间、裁定者或共同裁定方式、裁定状态及数字分（如适用）、裁定理由、依据原句、未解决问题。

两人未能达成一致时记录“未解决”，不要虚构裁定。若使用第三方裁定，登记该裁定者标识；其裁定不能冒充两名初始评分者独立一致。

裁定文件独立保存，不覆盖原始评分文件。不得以裁定后的相同值重算并冒充原始一致率。讨论若暴露规则歧义，原样记录歧义及适用范围；需要规则改动时升级评分表和协议版本，在新批次独立验证，不追溯改写旧评分。
