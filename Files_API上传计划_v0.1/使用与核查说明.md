# Files API上传计划 v0.1

**教学准备，不是研究样本或实验结果；未上传、未调用模型、未冻结。**

本轮只读取已有管理清单、其中明确列出的两张教学图片和四份文本，共七个文件。不读取其他来源引用、凭据或环境变量，不扫描候选池，不作视觉定位。

## 交付物

- [prepare_upload_plan.py](prepare_upload_plan.py)：Python标准库本地计划生成入口。
- [check_upload_plan.py](check_upload_plan.py)：可重复的本地核查脚本。
- [上传计划与任务关联.json](上传计划与任务关联.json)：两条待上传记录及四项任务关联。
- [离线核查记录.json](离线核查记录.json)：实际执行输出、输入前后哈希及主要产物哈希。

## 图片如何复用

按“batch_id＋image_id”归并。同批同图片编号的路径和SHA-256必须一致；发现不一致则停止。不同图片编号保持各自记录，不按文本哈希合并任务。

| 图片 | 拟上传名 | 字节数 | 关联任务 |
| --- | --- | ---: | --- |
| DEMO01 | DEMO01.png | 259 | BASE对应教学文本_01；ENHANCED对应教学文本_02 |
| DEMO02 | DEMO02.png | 444 | BASE对应教学文本_03；ENHANCED对应教学文本_04 |

计划中的uploads保存本地图片路径、哈希、字节数、匿名拟上传名、file_id=null和“待上传”状态。tasks保留原任务编号、条件编号、文本路径与哈希，通过相同批次和图片编号关联uploads，状态为“尚未调用”。

计划上传文件数为2，关联定位任务数为4；实际上传数和实际模型调用数均为0。文件ID为空表示还没有服务器返回值，不是失败或拒答。

同一条件的两份文本可以具有相同哈希；图片不同，因此仍是不同任务。将来上传所得真实ID应另存运行登记，关联本地图片编号及哈希，保留本轮计划原样。当前不实现填入ID或发送请求。

## 使用与复现

本轮实际使用Python 3.10.0及标准库，其他版本未验证。入口将控制台输出设为UTF-8。在本目录执行：

```powershell
python -B .\prepare_upload_plan.py --manifest '..\离线文本组装_v0.1\教学文本草案\组装清单_管理用.json' --output '.\上传计划与任务关联.json'
python -B .\check_upload_plan.py
```

第一条是本轮生成命令的等效本目录写法，实际生成成功，退出码0。交付计划已存在，再次指定同一输出文件会拒绝覆盖，退出码2。若要复现生成，显式改用本目录内尚不存在的输出文件；输出父目录需事先存在。

入口接受--manifest和--output，不实现联网、上传或模型调用。相对输入路径按管理清单所在目录解析，输出必须位于本程序目录内。先读取并校验图片及文本预期哈希，再复查所有输入未变化，最后独占创建输出文件。发现错误时不补写计划；若写入时发生异常，可能留下不完整文件，应保留错误记录并另选新输出位置。

输入限定为未调用的任务清单。脚本记录的文件扩展名用于拟上传名，不代表已经核验图片实际格式或元数据。
