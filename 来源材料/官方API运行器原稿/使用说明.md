# 一张开发图的 API 试跑

阶段：开发流程检查。使用 OpenAI 官方 Responses API，不用于宣布方法优劣。

## 任务说明

- 输入：`inputs/001.png`、`inputs/appendix.md`、`prompts/A.txt`、`B.txt`、`C.txt`。
- 输出：每次执行保存在新的 `runs/日期时间/` 目录；包括输入摘要、请求正文（图片用文件标识）、原始响应、文本输出、用量、耗时与检查结果。
- 验收：三版使用完全相同的图片字节、附录和参数；每版独立请求，无历史对话、无工具、无标准答案；首次结果完整保存，错误与截断保留，无自动重试。

## 固定条件

- 模型：`gpt-6.1-sol`，不自动更换模型。
- 推理强度：`low`；图片 detail：`high`。
- 输出上限：4096 tokens，包括推理和可见输出。这是开发初值，不保证足够；出现截断时先检查，不把截断当定位错误。
- 每次只发一个 user 消息：对应提示词、相同附录、相同图片。没有 `conversation` 或 `previous_response_id`。
- 原 PNG 较大，使用 Files API 上传一次，purpose 为 `vision`，三版引用同一 `file_id`。图片字节保持不变，不裁剪、不缩放、不重新压缩。
- 正常结束、错误停止或可处理的中断时，尝试删除上传文件，并记录 `upload_cleanup.json`。强制结束进程、网络断开或上传超时时可能无法确认清理，须检查 API 账户中的 Files；不声称一定删除成功。
- `tools=[]`，不执行任何模型提出的工具调用；`store=false` 不等于零数据留存。
- 不设置 temperature 或 seed，不声称推理确定。记录请求的模型与响应返回的模型标识；模型别名可能变化。
- 首次开发顺序固定 A、B、C；正式多图测试前另定交错/随机顺序，避免时间及缓存顺序偏差。耗时包含网络传输，不能直接当模型计算时间。

## 使用

只需已有 Python 3.10，不用安装第三方库。在终端进入本目录：

```powershell
python -B run_trial.py
```

默认只做本地检查，不联网、不需要密钥，不生成实验响应。

确认输入与三份提示词后，运行：

```powershell
python -B run_trial.py --run
```

`--run` 会上传一次图片并最多发三次推理请求，随后尝试删除上传文件，产生 API 用量。若未设置本机 `OPENAI_API_KEY`，脚本会在交互终端隐藏输入密钥；不要把密钥写进提示词、脚本、记录或聊天，也不要使用命令行参数传密钥。隐藏输入只在当前进程内使用，不保存。环境变量如已设置，只使用该变量，不读取 Codex 登录凭据。

若返回 401、403、429 或超时，保留记录，停止；不会自动换模型或重试。超时不能证明服务器未完成或未收费。失败后重新运行是新的尝试，不能覆盖首次结果。

## 阅读输出

先看 `summary.json` 中的完成状态、`incomplete_details`、空输出、缺失字段及意外输出类型，再读 A/B/C 原始文本。字段检查只找标签，不验证分数范围、候选数量、行政区写法或推断正确性，仍须人工检查。原始响应始终保留。

程序不加载真值、不自动评分。现有位置标签仍属暂定，开发结果不能证明可靠性提高。三次结果也不能估计随机波动。

## 本轮 30—60 分钟任务

先读三份提示词和固定条件，执行本地检查，再在自己的终端完成一次 `--run`。将首次运行的 `summary.json` 和三份输出交给导师；不要为了答对追加提示或反复重跑。
